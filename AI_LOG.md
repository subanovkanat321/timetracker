# Журнал работы с ИИ

Как писался этот проект: какие запросы давались ИИ, что он предложил, где ошибся и как ошибка
была найдена. Записи добавляются по ходу работы, а не задним числом. Сюда попадают только
реально случившиеся ошибки.

**Инструменты:** Claude Code (агент для разработки от Anthropic, модели семейства Claude) и
набор команд [gstack](https://github.com/garrytan/gstack) для Claude Code:

| Команда | Что делает |
|---|---|
| `/office-hours` | Разбор задачи и дизайн-док |
| `/plan-eng-review` | Ревью архитектуры и плана тестов до кода |
| `/review` | Ревью диффа |
| `/qa` | Проверка в браузере |
| `/ship` | Коммит, пуш и PR |

Дизайн-док дополнительно проверял отдельный агент-ревьюер: он не видел переписку и читал
только документ и код.

## Запросы

Дословно, как они давались:

1. `/office-hours` + полный текст задания. Результат: дизайн-док. Стек — Spring Boot +
   Thymeleaf + Postgres. Повторный запуск таймера запрещает индекс в базе. Отчёт режет записи
   по границам периода, дни считаются по Бишкеку.
2. `https://github.com/subanovkanat321/timetracker.git продолжай`. Результат: каркас
   приложения.
3. `учти еще команды gstack запускай его команды все по порядку`. Результат: перед тестами
   прошло ревью архитектуры (`/plan-eng-review`) с независимым вторым мнением.

## Ошибки ИИ и как они найдены

### 1. Чтение после ошибки в «сломанной» транзакции (дизайн)
- **Что предложил ИИ:** при повторном «Старте» поймать ошибку уникального индекса и тут же,
  внутри той же транзакции, прочитать идущий таймер, чтобы показать его в сообщении.
- **Что не так:** после ошибки Postgres помечает транзакцию прерванной. Любой следующий запрос
  в ней падает с `current transaction is aborted`.
- **Как найдено:** ревью дизайн-дока отдельным агентом (`/office-hours`, раунд 1).
- **Исправление:** сначала ошибку ловили снаружи транзакции. Потом решение заменили целиком,
  см. №5.

### 2. Тесты внутри `docker build` (дизайн)
- **Что предложил ИИ:** многоступенчатый `Dockerfile` с обычной сборкой Maven.
- **Что не так:** обычная сборка запускает тесты, а тестам на Testcontainers нужен Docker,
  которого внутри `docker build` нет. `docker compose up --build` упал бы у проверяющего.
- **Как найдено:** то же ревью дизайн-дока.
- **Исправление:** в `Dockerfile` сборка идёт с `-DskipTests`. Тесты гоняет
  `./mvnw verify` локально и в CI.

### 3. Критерий, подталкивающий к выдумыванию (дизайн)
- **Что предложил ИИ:** критерий готовности «в журнале не меньше 3 ошибок ИИ».
- **Что не так:** число настоящих ошибок от автора не зависит. Такой критерий подталкивает
  дописывать журнал задним числом.
- **Как найдено:** то же ревью.
- **Исправление:** в журнал пишется каждая реально найденная ошибка, без минимального числа.

### 4. Один и тот же запрос к базе дважды
- **Что сделал ИИ:** в первой версии `ReportService.build` вызывал `findOverlapping` дважды:
  один раз для строк отчёта, второй — для итогов.
- **Как найдено:** самопроверка диффа сразу после написания.
- **Исправление:** один проход по записям собирает и строки, и итоги.

### 5. Слишком сложная защита от повторного старта
- **Что сделал ИИ:** класс `TimerFacade` без транзакции ловил `DataIntegrityViolationException`,
  по цепочке причин находил `ConstraintViolationException` Hibernate, сверял имя ограничения и
  новой транзакцией читал идущий таймер.
- **Что не так:** код работал, но в нём три движущиеся части, и его трудно объяснить и менять.
- **Как найдено:** независимое второе мнение в `/plan-eng-review`.
- **Исправление:** `INSERT … ON CONFLICT (employee_id) WHERE ended_at IS NULL DO NOTHING
  RETURNING id`.
  - Если таймер уже идёт, вставка просто ничего не делает, и транзакция остаётся рабочей.
  - Защиту от гонки по-прежнему даёт индекс.
  - `TimerFacade` удалён. Добавление сотрудника переведено на тот же приём.

### 6. Строки отчёта не сходились с итогом
- **Что сделал ИИ:** каждая строка показывала время без секунд, а итог складывал точные секунды
  и обрезал их только в конце. Три записи по 40 с давали в строках «0 ч 00 мин», а в итоге
  «0 ч 02 мин».
- **Как найдено:** второе мнение в `/plan-eng-review`.
- **Исправление:** время везде показывается с секундами: «5 ч 35 мин 05 с».

### 7. Короткие записи пропадали из отчёта
- **Что сделал ИИ:** отчёт скрывал строки с нулевой длительностью в периоде. Чтобы убрать
  идущий таймер в будущем периоде, он заодно прятал записи, где «Старт» и «Стоп» нажаты в одну
  секунду.
- **Как найдено:** второе мнение в `/plan-eng-review`.
- **Исправление:** скрывается только идущий таймер, если период ещё не наступил.

### 8. `;jsessionid=` в адресе после действия
- **Что сделал ИИ:** flash-сообщения после редиректа хранятся в сессии. При первом редиректе
  Tomcat не знает, принимает ли браузер cookie, и дописывает номер сессии в адрес:
  `http://localhost:8080/;jsessionid=…`.
- **Как найдено:** ручной запуск приложения на Postgres, вывод `curl -w '%{redirect_url}'`.
- **Исправление:** `server.servlet.session.tracking-modes: cookie` в `application.yaml`.
